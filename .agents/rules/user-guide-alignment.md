# Product Pillars & User Guide Alignment Rule

Whenever modifying code, designing features, or refactoring this application:

## 1. Core Product Pillars & Human-Centered Design
Verify that any requested feature or change aligns with the 4 foundational pillars defined in [USER_GUIDE.md](file:///c:/Users/IsItI/Documents/GitHub/Workoutapp/USER_GUIDE.md) and [Spec.txt](file:///c:/Users/IsItI/Documents/GitHub/Workoutapp/Context/Spec.txt):

1. 🎯 **Action Over Overanalysis (Cognitive Relief)**:
   - **Rule**: Never clutter views with unnecessary choices or decision fatigue. Always present a distilled, clear, immediate action path (like the Up-Next Card: session focus, duration, prep tips, hydration, and effort-matched meal advice).
2. ⚡ **Frictionless Initiation (ADHD-Friendly Design)**:
   - **Rule**: Support users with executive function challenges or time perception difficulties. Explicitly communicate required time upfront, keep entry friction minimal, and ensure starting a workout requires zero hesitation or dread.
3. 🛡️ **Guilt-Free Habit Building (JIT Sequential Progression)**:
   - **Rule**: Treat progress as a continuous line, never a rigid calendar grid. NEVER introduce calendar date lockouts, red missed-day marks, or broken streak penalties that trigger shame or all-or-nothing quitting.
4. 🌿 **Holistic & Empathetic Daily Support**:
   - **Rule**: Treat the athlete as a complete human. Balance workout intensity with real-time RPE feedback, physical movement prep tips, hydration needs, and daily nutrition strategies tuned to their effort level.

---

## 2. Mandatory Documentation Updates
* Whenever new features, tabs, UI components, or workflow options are introduced or modified, update [USER_GUIDE.md](file:///c:/Users/IsItI/Documents/GitHub/Workoutapp/USER_GUIDE.md) to keep it in sync.
* Ensure all page goals, button actions, and user instructions in [USER_GUIDE.md](file:///c:/Users/IsItI/Documents/GitHub/Workoutapp/USER_GUIDE.md) reflect live app functionality.

---

## 3. Conflict Resolution Protocol
If a proposed change contradicts the app's core philosophy (e.g., adding decision-heavy menus, hidden durations, or calendar guilt):
1. Immediately flag the contradiction to the user.
2. Explain why it conflicts with the human-centered ADHD-friendly design philosophy.
3. Propose an alternative implementation that achieves the user's goal while preserving simplicity, clarity, and guilt-free continuity.
